# Verify and integrate

Read the requested outcome and acceptance criteria before reviewing results. Inspect final artifacts, not just a specialist's completion message. Check interfaces between independently produced pieces and ensure assumptions agree.

Select checks proportionate to the result: reproduce changed behavior for code, validate relevant data calculations, inspect rendered output for visual artifacts, and confirm current sources for factual claims. A syntax check is evidence about syntax, not proof of functional success. Avoid tests that merely match prompt wording.

When review independence materially helps, use an authorized reviewer with the brief and final artifacts, without steering them toward a preferred conclusion. Resolve actionable findings and rerun affected checks; do not repeat broad checks without a new reason.

Verify each acceptance criterion or mark it explicitly unmet. Distinguish checks executed, checks unavailable, and behavior inferred. Do not describe a package as installed, an agent as active, or a deployment as published without runtime evidence.

Combine the results into one coherent deliverable. Explain what changed, why it meets the goal, what was checked, and any material limitation. Retain only task state needed for resumption; never mark work complete while required delegated tasks remain outstanding.
